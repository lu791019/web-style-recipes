# 08 動態文字（Kinetic Typography）

> 出處：AI郵報〈10 種 Vibe Coding 網站設計靈感〉，Joanna Chang，2026-10-14，https://www.aiposthub.com/vibe-coding-website-ideas/ 。本檔為改寫整理，非原文。

- **分類**：文字類
- **適合用途**：寫作者／設計師作品集、品牌宣言頁、講座或書籍發表頁、以文字為核心的個人首頁

## 視覺特徵清單
- 黑底、米白字，全頁只有一個螢光點綴色
- Hero：大量微型文字（品牌名、關鍵字反覆）聚合成一個大字或圖形
- 游標靠近時文字被推開，停止後慢慢回到原位
- 層級分明：一個超大主標、一行副標、極少量內文
- 模式切換：群聚、故障（glitch）、重力

## 一句話流程
進場看到微型文字聚成主標圖形 → 游標掃過把字推散 → 停下後字回位 → 切換模式（群聚／故障／重力）→ 往下讀內容

## 迭代順序
1. **先完成靜態排版與層級**（沒有動態也要好看、可讀）
2. 微型文字取樣成形：主標輪廓內的取樣點密度
3. 一種主要互動：游標排斥＋回位（彈簧係數、阻尼）
4. 螢光色使用位置
5. 其他模式（故障、重力）
6. 手機、減少動態

## 技術棧
- 取樣：把主標或圖形畫到離屏 canvas，`getImageData` 取有墨的點，每點分配一個微型字
- 繪製：Canvas 2D `fillText`（數千字）；字多時預先把每個字元畫成小圖再 `drawImage`
- 物理：每粒子有原位、位置、速度；排斥力 ∝ 1/距離²（限半徑），回位用彈簧＋阻尼
- 故障模式：隨機水平切片位移＋RGB 分離；重力模式：粒子落到底部堆疊，點擊後回原位
- 真正的主標同時存在於 DOM（可選取、可被讀屏器讀到），canvas 設 `aria-hidden`

## 專屬陷阱
- 只有 canvas 沒有 DOM 文字 → SEO 與讀屏器都看不到主標
- 中文字型在 canvas 載入前就畫會變系統字：等 `document.fonts.ready` 再取樣
- 粒子太多掉幀：桌機約 2,000–4,000，手機 1/3；字元快取成小圖
- 故障模式閃爍頻率過高有光敏風險：每秒閃動少於 3 次，且可關
- 回位彈簧太硬會抖、太軟回不去：阻尼約 0.85–0.9

## prompt 範本
```
做一個單一 HTML 檔（內嵌 CSS 與 JS）的「動態文字」首頁，品牌名 {品牌名}，主標 {主標}，關鍵字 {3–6 個關鍵字}。

視覺：
- 黑底、米白字，全頁只用一個螢光點綴色 {例如螢光黃綠 #D4FF3A}
- Hero：用數千個微型文字（品牌名與關鍵字反覆）聚成主標的大字輪廓
- 層級：超大主標 → 一行副標 → 少量內文；先確保靜態排版就成立

互動（先只做一種主要互動）：
- 游標靠近時微型字被推開，停止後以彈簧回到原位
- 右上模式切換：群聚（預設）、故障（切片位移＋RGB 分離，每秒閃動少於 3 次）、重力（字掉到底部，點擊回位）

技術約束：
- 主標同時以真正的 DOM 文字存在（可讀、可選取），canvas 設 aria-hidden
- 等 document.fonts.ready 後再取樣字形
- 粒子：桌機約 3,000，手機約 1,000；字元預先快取成小圖
- 手機：觸控拖曳即排斥；Pointer Events；100dvh Hero
- prefers-reduced-motion：直接顯示聚好的靜態主標，關閉故障模式

不可做：不要多色彩虹字；不要讓內文也變粒子（內文要穩定可讀）；不要自動狂閃。
```

## Claude Design brief 卡
```markdown
# 視覺 brief：{專案名}

- **風格**：動態文字（微型字聚合成主標，會被游標推散）
- **情緒關鍵字**：銳利、編輯感、聲量、克制
- **配色**：黑 #0A0A0A；米白 #F2EDE4；單一螢光點綴 {#D4FF3A}
- **材質**：純排版，無圖片；可有極細網格
- **版面**：滿版 Hero 主標；下方編輯式排版的內容；手機同構縮放
- **核心互動**：游標推散微型字、停下回位；三種模式切換
- **一句話流程**：進場見聚合主標 → 推散 → 回位 → 換模式 → 往下讀
- **不可做**：多色、內文粒子化、高頻閃爍
- **要交付的畫面**：靜態首屏、推散中、故障模式、重力模式、手機首屏
```
