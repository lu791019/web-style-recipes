# 五段式方法：把一個「怪點子」變成可用的互動首頁

> 本方法整理自 AI郵報〈10 種 Vibe Coding 網站設計靈感〉（Joanna Chang，2026-10-14）的做法精神，結構與用語為改寫整理。
> 出處：https://www.aiposthub.com/vibe-coding-website-ideas/

核心信念：**風格靠「看得見的特徵」撐起來，記憶點靠「一個完整的小流程」撐起來。** 先把這兩件事講清楚，AI 才不會產出「長得像，但沒有魂」的頁面。

---

## 第零段：還沒定方向？先發散

風格還沒選、或 Dex 說「多給幾個方向」時，不要直接進第一段——先走 `explore.md` 的探索模式：
靈感盤點 → 3～4 個方向並排讓 Dex 挑 → 同方向 5 個變體。選定後，再用下面五段把它做出來。
決策與捨棄的方向寫進該案的 `design-decisions.md`，之後的輪次先讀它。

## 第一段：視覺特徵清單（看得見的東西）

把風格拆成 5–8 個**可以指著螢幕說「就是這個」**的元素，而不是形容詞。

| 寫法 | 例子 | 結果 |
|---|---|---|
| 形容詞（弱） | 「復古、有質感」 | 每次生成都不一樣 |
| 可見元素（強） | 「深紅絨布簾、黑白棋盤地板、拉絲金屬機身」 | 風格穩定、可驗收 |

清單建議涵蓋五類：**底色與主色**、**材質**（顆粒、網點、玻璃、金屬）、**招牌元素**（布簾、郵戳、取景框）、**字體角色**（等寬讀數、手寫、精品襯線）、**氛圍細節**（掃描線、殘影、光暈）。

## 第二段：一句話流程（使用者會經歷什麼）

用箭頭寫出「進場 → 動作 → 回饋 → 收穫」，一行寫完。

- 好：「進場看到熱像 → 移動游標加熱 → 點擊投下熱源 → 主角飛過留下殘影 → 切換色盤」
- 壞：「有很多互動效果」

一句話流程就是驗收標準：做完後照著箭頭走一遍，每一步都要有畫面回饋。

## 第三段：一次只改一件事（迭代順序）

第一版只求流程走得通。之後每輪只調**一個維度**，調完看畫面再決定下一步。通用順序：

1. **骨架**：版面、單屏或捲動、主要區塊位置
2. **主角**：最有記憶點的那一個元素（熱點、郵票、布簾）
3. **主要互動**：只加一種，確認手感
4. **質感層**：顆粒、掃描線、光暈、陰影
5. **次要互動與彩蛋**：模式切換、秘密房間、色盤
6. **降級與手機**：reduced-motion、觸控、效能、權限被拒

每個風格檔的「迭代順序」會覆寫這份通用順序（例如音檔可視化要先調點的疏密亮度）。

## 第四段：prompt 組裝

一份可直接貼的 prompt 由六塊組成，順序固定：

```
1. 角色與產物：做一個單一 HTML 檔（內嵌 CSS／JS），主題是＿＿，給＿＿用
2. 視覺特徵：（第一段清單，逐條）
3. 一句話流程：（第二段）
4. 互動細節：每個動作的觸發方式與畫面回饋
5. 技術約束：技術棧、效能預算、手機版行為、權限被拒處理、reduced-motion
6. 不可做：常見走味方向（例如「不要做成科技藍漸層 SaaS 風」）
```

內容（品牌名、文案、素材）放在第 1 塊，用變數標示 `{品牌名}`，方便替換。

## 第五段：技術陷阱

每個風格都有「做出來才會撞到」的坑。共通陷阱見 `pitfalls.md`；風格專屬陷阱寫在各風格檔。**交付前逐條自查**，不要等使用者回報。

## Claude Design brief 卡模板

給 Claude Design 做視覺探索用。只描述「要長什麼樣、要有什麼感覺」，不寫程式細節。

```markdown
# 視覺 brief：{專案名}

- **風格**：{風格名}（參考：{一句話描述}）
- **參考經典**：{作者〈作品〉年份；從 aesthetics.md 挑，或自行查證。只借骨架：配色、構圖、字體氣質、動態節奏}
- **情緒關鍵字**：{3–5 個詞}
- **配色**：{主色 hex／名稱、輔色、點綴色、背景}
- **材質**：{顆粒、網點、金屬、玻璃、紙張……}
- **版面**：{單屏或捲動、區塊配置、桌機與手機差異}
- **核心互動**：{最重要的 1–2 個互動，用畫面描述}
- **一句話流程**：{進場 → … → 收穫}
- **不可做**：{走味方向、禁止元素}
- **要交付的畫面**：{例如：桌機首屏、互動進行中、結果畫面、手機首屏}
```

填寫原則：
- 「參考經典」一定要填，而且要具體到作品與年份（「Müller-Brockmann〈beethoven〉1955」比「瑞士風」好）；Claude Design 拿到出處才不會給平均值
- 配色寫具體值或具體名稱（「郵務深藍」比「藍色」好）
- 「不可做」至少兩條，最能防止走味
- 「要交付的畫面」對應一句話流程的關鍵節點，讓探索結果可以直接接回實作
